# 🧪 Главный Банк Тестирования (Test Plan)

> **Главный хаб автотестов проекта.** Этот документ служит оглавлением для всех тест-кейсов. Сами сценарии хранятся в папке `tests_bank/`.

---

## 🤖 Как агент должен проводить тестирование
1. **Изучение фичи:** Агент читает код фичи или её описание в `MEMORY_BANK.md` (или `memory_bank/`).
2. **Определение скоупа тестирования:**
   - **Точечное тестирование (после создания фичи):** Агент находит соответствующий файл с тест-кейсами в `tests_bank/` по оглавлению ниже. Если файла нет — создает его. Тестируется только затронутый блок.
   - **Сквозное тестирование (End-to-End, перед релизом):** Агент последовательно проходит все активные тест-кейсы из `tests_bank/` (или запускает специальный сквозной сценарий, если он описан) для проверки всего приложения от старта до конца.
3. **Запуск приложения:** Приложение запускается командой `flutter run -d chrome`.
4. **Прохождение сценария:** С помощью MCP-сервера Playwright агент кликами проходит до тестируемой фичи и выполняет описанные в кейсах шаги.
5. **Проверка (Validations):** Агент оценивает:
   - **Визуальную часть:** выглядит ли всё по дизайну/ожиданиям (размеры, цвета, отступы).
   - **Функциональную бизнес-логику:** правильно ли отработало нажатие, изменился ли стейт, произошел ли нужный переход.
6. **Отчёт:**
   - ✅ **В случае успеха:** выдаётся краткий отчёт о том, что всё чётко сработало.
   - ❌ **В случае ошибки:** создаётся детальный отчёт о падении и предлагается пошаговый план исправления.

## 🛠️ Структура файла тест-кейса
Каждый файл в `tests_bank/` описывает одну фичу/блок и должен содержать:
- **Описание:** Какую логику покрывает этот файл.
- **Пререквизиты:** Что должно быть настроено перед тестом (расширения, стейт игры).
- **Позитивные кейсы:** Сценарии успешного выполнения (happy path).
- **Негативные кейсы:** Сценарии обработки ошибок (неверный ввод, отмена).
- **Особые сценарии (Edge cases):** Множественный выбор, быстрое перекликивание, граничные значения.

---

## ⚠️ Правила масштабирования
1. **Не пишите кейсы здесь.** `plan_for_tests.md` — это **ТОЛЬКО** оглавление и правила.
2. **Один блок логики = один файл.** Создавайте отдельный файл в `tests_bank/` для каждой новой логики приложения (например, `tests_bank/timer_logic.md`).
3. **Синхронизация с памятью.** При добавлении новой фичи и обновлении `MEMORY_BANK.md` агент **обязан** синхронно создать файл тест-кейсов и добавить его в оглавление `plan_for_tests.md`.

Эту команду вы можете скопировать и запустить (через агента) после завершения любой фичи:

```text
Проверь последние изменения в проекте и обнови `plan_for_tests.md` и соответствующие файлы в `tests_bank/`, синхронизировав их с `MEMORY_BANK.md`. Убедись, что для новой логики добавлены тест-кейсы (как позитивные, так и негативные, визуальные и функциональные).
```
