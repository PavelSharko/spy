w# 📈 Руководство по обогащению Памяти (Memory Enrichment Guide)

> Память ИИ в проекте не возникает из ниоткуда. Она строится инкрементально. Этот файл описывает, как агенты выращивают базу знаний.

## 1. Инициализация (Первый вход в Legacy-проект)
Если `tmp_starter_kit` скопировали в уже существующий огромный проект, `main_agent` **НЕ ДОЛЖЕН** пытаться прочитать тысячи файлов за один раз и описать всё.
**Правило "Lazy Loading":**
- Сначала заполняется только базовая парадигма (язык, фреймворк).
- По мере постановки конкретных бизнес-задач (например, "переделай профиль пользователя"), `main_agent` исследует этот узкий модуль и детально описывает его архитектуру в `project_architecture.md` и бизнес-правила в `system_logic.md`.

## 2. Инкрементальное обновление (Для саб-агентов)
Каждый раз, когда саб-агент (кодер) блестяще завершает задачу, он задает себе контрольный вопрос:
*"Ввёл ли я новые архитектурные сущности, или переопределил старые?"*

- **Если добавлен новый Экран или Сущность БД** -> Агент молча идет и дописывает строчку в `project_architecture.md`.
- **Если придуман новый способ инжекта зависимостей** -> Агент описывает его в `code_patterns.md`, чтобы завтра другой агент не сгенерировал код в другом стиле.
- **Если изменилась бизнес-логика (например, очки стали считать по-другому)** -> Напрямую редактируем `system_logic.md`.

**Строгое правило обогащения:**
Не удаляйте старый контекст проекта без необходимости. Дополняйте файлы структурированно (списками и таблицами), сохраняя максимальную лаконичность для экономии токенов. Не пишите туда код — только ссылки на файлы и краткие описания логики!
