## Протокол работы с проектом

### 1. Перед началом работы

1. **Прочти** `MEMORY_BANK.md` — это оглавление всей документации
2. **Найди** нужные файлы в `memory_bank/` по таблице «Быстрый старт»
3. **Изучи** паттерны в `code_patterns.md` — они обязательны к следованию
4. **Пойми** игровой поток в `business_logic.md`, если работаешь с логикой игры

### 2. Во время работы

- Следуй **существующим паттернам** — не вводи новые архитектурные решения без обсуждения
- Все строки — через `AppStrings`
- Все константы — через `GameRules`, `GameSounds`, `AppImages`
- Каждая кнопка — `SoundService.instance.playClick()`
- Фон экрана — `AppStyles.mainBackgroundDecoration`
- Навигация — `Navigator.push` + `MaterialPageRoute`
- Не забывай `ExitGameButton` на игровых экранах

### 3. После завершения фичи — ОБЯЗАТЕЛЬНО

> ⚠️ **После каждой завершённой фичи агент ОБЯЗАН проверить:**

- [ ] Нужно ли обновить `memory_bank/project_structure.md`?
  - Добавлен новый файл/директория?
  - Изменена структура?
- [ ] Нужно ли обновить `memory_bank/code_patterns.md`?
  - Введён новый паттерн?
  - Изменён существующий?
- [ ] Нужно ли обновить `memory_bank/business_logic.md`?
  - Изменены правила игры?
  - Добавлен новый экран в поток?
  - Изменена система очков?
- [ ] Нужно ли обновить `MEMORY_BANK.md`?
  - **Только** если добавлен новый файл в `memory_bank/`

## Чего НЕЛЬЗЯ делать

| ❌ Нельзя | ✅ Вместо этого |
|---|---|
| Хардкодить строки в виджетах | Добавить в `AppStrings` |
| Хардкодить пути к ассетам | Добавить в `AppImages` / `GameSounds` |
| Хардкодить числовые константы | Добавить в `GameRules` |
| Создать новый синглтон через constructor | Использовать паттерн `ClassName._() + static final instance` |
| Менять `MEMORY_BANK.md` с деталями | Дополнять файлы в `memory_bank/` |
| Использовать именованные маршруты | `Navigator.push` + `MaterialPageRoute` |
| Забыть звук на кнопке | `SoundService.instance.playClick()` |

## Как добавить новый файл в memory_bank/

1. Создай `memory_bank/new_topic.md`
2. Добавь строку в таблицу `MEMORY_BANK.md` → секция «База знаний»
3. Если нужно — добавь в таблицу «Быстрый старт»

## 🛠 Сборка и загрузка APK (команда «собери апк»)

Когда пользователь даёт команду **«собери апк»** или аналогичную, агент обязан выполнить следующие шаги:

1. **Собрать релизные сборки APK с разделением по архитектурам (для уменьшения веса до ~50МБ)**:
   ```bash
   flutter build apk --release --split-per-abi
   ```
2. **Запустить загрузку ARM64 сборки (основная архитектура современных телефонов) на Google Drive** с помощью Python-скрипта:
   ```bash
   python3 scripts/upload_apk.py build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
   ```
   *Скрипт автоматически:*
   - Авторизуется через `token.json` и клиентские секреты Google Drive.
   - Найдёт или создаст папку `test_apks` в корне диска.
   - Определит следующий номер сборки (например, загрузит файл как `spy_3.apk`).
   
3. **Предоставить пользователю прямую ссылку на скачивание**:
   После успешной загрузки и получения `File ID` из логов скрипта, агент обязан сформировать и вывести прямую ссылку на файл:
   `https://drive.google.com/file/d/<FILE_ID>/view?usp=drivesdk`

## Приоритет при конфликтах

1. **Код** — всегда является источником истины
2. **memory_bank/** — документация (может отстать от кода)
3. **MEMORY_BANK.md** — только оглавление

> Если документация расходится с кодом — обнови документацию, а не код.
